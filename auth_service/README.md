номер телефона - пока является почтой
1) Регистрация/Вход
- Пользователь вводит номер телефона
- Фронт отправляет запрос на StartAuthentication
- Создается одноразовый короткоживущий код подтверждения
- Код сохраняется в виде хеша с ограниченным TTL (таблица: phone number|hash)
- Отправляется код на номер телефона
- Пользователь вводит полученный код
- Код отправляется на CompleteAuthentication
- АПИ проверяет токен, после код становится недействительным
- Если пользователя не существует, то создается пользователь
- Создаются access_token и refresh_token и отправляются клиенту

2) У пользователя истек access_token
- АПИ сообщает клиенту, что у пользователя истек access_token
- Клиент делает запрос в RefreshTokens с refresh_token
- АПИ сопоставляет refresh_token с пользователем
- АПИ обновляет refresh_token и access_token, refresh_token хешируется в бд
- АПИ отдает клиенту access_token и refresh_token

3) У пользователя истек refresh_token
- Клиент пытается обновить токены через RefreshTokens
- АПИ определяет, что refresh_token истек, отсутствует или недействителен
- АПИ возвращает ошибку авторизации
- Клиент удаляет локальные access_token, refresh_token и связанные с авторизацией данные
- Клиент требует повторного входа в аккаунт, то есть возвращается к пункту 1)

4) Получить все текущие сессии
- Клиент делает запрос на GetSesions()
- Возваращается список всех текущих сессий

5) Отзыв конкретной сессии
- Клиент вызывает RevokeSession(session_id)
- АПИ проверяет, что сессия принадлежит пользователю
- API отзывает сессию
- refresh_token этой сессии становится недействительным
- если это текущее устройство, то так же на клиенте удаляется access_token

6) Выход со всех других устройств
- Пользователь вызывает RevokeOtherSessions
- АПИ отзывает все сессии пользователя кроме текущей
- Текущая сессия продолжает работать

### Вход для сотрудников
- Все тоже самое, но в запросе передается контекст это клиент или сотрудник

## Обычный вход без прав
1) Регистрация
- Пользователь передает данные для регистрации в RegisterUser
- Происходит создания пользователя в бд, создается ActivationToken для подтверждения
- ActivationToken отправляется на почтовый адрес и хешируется в бд
- Пользователь получает ActivationToken и отправляет его в ActivateUser
- Пользователь получает в ответ подтверждение активации аккаунта

2) Вход в аккаунт (получение токена)
- Пользователь передает данные для входа в CreateAuthenticationToken
- АПИ проверяет, что пользователь активирован, иначе ошибка и пункт 3
- АПИ создает access_token и refresh_token, refresh_token хешируется в бд
- Пользователь в ответ получает access_token(JWT) и refresh_token
- Отправляется письмо, что осуществлен вход в аккаунт с кнопкой это был не я (п. 8)

3) Пользователь нe активировал свой аккаунт во время (ActivationToken просрочился) (endpoint CreateActivationToken имеет rate limit)
- Пользователь отправляет данные для входа в CreateAuthenticationToken
- АПИ отдает ошибку, что пользователь не активирован
- Клиент показывает что нужно активировать аккаунт делает запрос на CreateActivationToken
- Создается ActivationToken и отправляется на почтовый адрес и хешируется в бд
- Пользователь получает ActivationToken и отправляет его в ActivateUser
- Пользователь получает в ответ подтверждение активации аккаунта

4) Пользователь забыл свой пароль
- Пользователь передает данные в CreatePasswordResetToken
- АПИ проверяет, что пользователь зарегестрирован
- PasswordResetToken отправляет на почтовый адрес и хешируется в бд
- Пользователь отправляет PasswordResetToken в UpdateUserPassword
- Сервер отправляет подтверждение смены пароля и удаляет refresh_token

5) У пользователя истек access_token
- АПИ сообщает клиенту, что у пользователя истек access_token
- Клиент делает запрос в RefreshTokens с refresh_token
- АПИ сопоставляет refresh_token с пользователем
- АПИ обновляет refresh_token и access_token, refresh_token хешируется в бд
- АПИ отдает клиенту access_token и refresh_token

6) У пользователя истек refresh_token
- Клиент пытается обновить токены через RefreshTokens
- АПИ определяет, что refresh_token истек, отсутствует или недействителен
- АПИ возвращает ошибку авторизации
- Клиент удаляет локальные access_token, refresh_token и связанные с авторизацией данные
- Клиент требует повторного входа в аккаунт, то есть возвращается к пункту 2)

7) Пользователь выходит из аккаунта
- Пользователь делает запрос в LogOut
- АПИ удаляет refresh_token
- Клиент получает положительный ответ и удаляет у себя все данные

8) Подозрение на компрометацию аккаунта
- в этой кнопке ссылка со специальным security_token
- Пользователь вводит новый пароль
- Фронт отправляет новые пароль и security_token на RecoverCompromisedAccount
- АПИ получает новый пароль и security_token
- АПИ удаляет все сессии и обновляет пароль

## 2FA:
1) Пользователь создает счет в банке
- Приложение указывает шаги для создания TOTP
- На сервере формируется секрут
- Пользователь подтверждает создание TOTP вводом кода

2) Пользователь хочет перевест деньги через браузер
- Для каждое операции запрашивает TOTP

3) Пользователь хочет перевести деньги через мобильное приложение
- TOTP требуется только для первоночального входа
- Создается долгоживующая сессия с подтверждение безопасноти

4) Пользователь хочет поменять TOTP
- Запрашивается TOTP
- Происходит смена TOTP

5) Пользователь хочет поменять TOTP, но он его потерял
- Требуется обратится в поддержку для подтверждения личности
